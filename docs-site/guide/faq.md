# 常见问题

## 浏览器打不开 Web 模式

先在服务器执行 `curl -I http://127.0.0.1:8088/`，确认 Terma 本身已启动；再检查宝塔站点的反向代理、HTTPS 证书和 WebSocket 开关。

## 飞牛浏览器可以登录，App 中继却提示来源不一致

这类提示发生在校验密码之前，不代表密码错误。浏览器和飞牛 App 可能使用不同入口：例如 App 发送的来源是 `https://relay.example.com:44989`，Terma 收到的访问地址却是 `192.168.1.10:8088`。

需要分别检查两项授权，不能只添加其中一项：

- **允许的访问域名或 IP（Allowed Hosts）**：填写“服务收到的域名”。例如保留 `terma.example.com`，再添加 `192.168.1.10:8088`。
- **允许的中继域名**：填写“App 或中继的来源”中的域名或 IP，例如 `relay.example.com`。

1. 通过局域网等可以打开的地址，进入 Terma“设置 → 安全”；也可以进入飞牛“应用中心 → Terma → 应用设置”的运行设置。
2. 在允许的访问域名或 IP 中，保留已有公网域名，并补上提示中的 NAS 地址。多个值用逗号分隔；若按端口限制访问，填写实际端口，例如 `192.168.1.10:8088`。
3. 在允许的中继域名中填写来源里的域名，例如 `relay.example.com`，不填写协议、端口或路径。
4. 保存设置。通过应用中心保存时，运行中的 Terma 会短暂重启；关闭 App 中原来的页面后重新打开，再用 Terma 原来的 Web 密码登录。

关闭“校验 HTTPS/HTTP 来源协议”只处理 HTTPS 转发到 HTTP 的协议差异，不能代替以上两项授权。若显示的是飞牛 FN Connect 自身的无权限提示，需要在飞牛远程访问中授权；Terma 不能代替飞牛授予权限，也不使用飞牛账号进行单点登录。

### 中继端口每次变化，是否需要反复修改

支持中继域名授权的版本允许只填写域名或 IP。`relay.example.com` 可适配该主机的不同 **HTTPS** 端口，无需每次修改端口。

旧的完整地址，例如 `https://relay.example.com:44989`，仍只授权该协议和端口；需要适配随机端口时，将它替换为域名形式。域名授权不包含其他子域名，也不自动允许 HTTP。只授权你信任的入口，登录密码验证始终保留。

### 飞牛运行设置为什么没有回显我设置的值

应用中心运行设置表单和 Terma Web 设置不是双向同步的同一个页面。应用中心显示的是通过该表单保存的输入；在 Terma“设置 → 安全”修改后，不能据此判断应用中心表单也会更新。

运行设置里的空白或“保持现有设置”表示此次不修改，不表示实际配置已经清空。请在 Terma“设置 → 安全”查看当前生效的允许域名、中继域名和协议校验设置；需要移除授权时，使用页面提供的删除或重置操作。

密码不会回显。修改密码字段留空时保留原密码；正常升级也保留原密码。报告问题时提供版本和脱敏后的来源、访问地址与报错即可，不要提供密码、Token 或私钥。

## SSH 能连接但终端没有输入输出

检查远端 shell、PTY 分配和连接保活设置。若使用跳板机或受限 shell，先在系统终端用同一用户和密钥验证 SSH，再回到 Terma 检查连接配置。

## VNC 提示密码错误

确认 VNC 密码与远端 VNC 服务配置一致。TigerVNC、noVNC 和系统客户端可能使用不同的认证入口；可在连接时重新输入密码，并选择是否更新保存的凭据。

## 如何报告问题

提交 Issue 时请提供 Terma 版本、操作系统、复现步骤和脱敏日志。不要上传私钥、访问 Token、密码、完整邮件日志或数据库备份。
