# 传输与同步任务

Terma 1.7.0 在桌面端提供统一的“传输与同步任务”工作区。定时上传、定时下载和文件夹同步使用同一份任务列表与新建表单，适合把重复的 SFTP 操作交给 Terma 按规则执行。

> 该功能需要 Terma 桌面端保持运行。窗口最小化不会停止任务；完全退出、关机或休眠期间不会执行任务，重新打开后会根据任务的错过执行策略处理。

## 从哪里打开

在桌面端工作区标题栏、命令窗口入口附近选择“传输与同步任务”。打开后可以查看任务状态、最近运行、下次执行时间、最近同步时间和需要处理的错误。

每个任务都可以：

- 立即运行、暂停或重新启用；
- 编辑方向、路径、周期、通知和同步保护选项；
- 查看该任务自己的运行记录；
- 调整任务顺序，顺序会跨刷新保持；
- 删除任务或清空该任务的历史记录。

## 新建任务

新建任务使用一套统一表单。先选择已保存的 SSH 连接，再选择本机路径和远端路径；临时快速连接不能用于无人值守任务。

### 方向

- **上传**：将本机文件或文件夹传到服务器。
- **下载**：将服务器文件或文件夹下载到本机。
- **双向**：在两侧之间安全合并变化。

后台会根据任务的路径和方向自动区分普通传输与安全同步，已有任务和同步基线不会因为统一界面而改变。

### 执行周期

支持以下方式：

- 一次执行；
- 秒、分钟、小时、天、周、月和年周期；
- 指定时间、倒计时和整点/半点；
- Cron 表达式；
- 实时（近实时）监控。

可以为计划任务设置开始时间。Cron 输入会实时校验，并显示最近三次预计执行时间，便于发现表达式或时区设置问题。

实时模式不是服务器推送：本机变化会唤醒检查，远端会按约 10 秒的间隔检查变化。因此它适合近实时同步，但不承诺每个远端变化都立即到达。

## 文件变化和同名文件

普通传输会记录成功的源端快照，未变化的文件会跳过；如果目标文件已经丢失，即使源端没有变化也会自动补传。安全同步会保存成功的双侧基线，并结合大小、修改时间和必要的内容校验判断变化。

同名文件默认按任务的安全策略处理。发生内容变化时，Terma 会根据任务设置覆盖、保留冲突副本或跳过，不会仅因为文件名相同就认定两侧内容相同。

## 删除传播和安全保护

删除传播默认关闭。上传和下载方向可以分别决定是否让源端删除影响目标端；启用后，Terma 只会对成功基线中存在、且剩余目标没有被用户修改的普通文件执行受保护删除。

任务还会跳过符号链接、目录联接、设备文件和常见临时文件，并检查本机路径、远端路径和任务重叠，避免意外访问或同步环路。冲突默认保留可识别的副本，单个冲突不会阻塞其他安全文件。

## 重启和错过执行

如果 Terma 关闭时错过了计划时间，任务可以选择：

- **恢复后补执行一次**：重新打开 Terma 后执行一次，不会把错过的每个周期全部补跑；
- **跳过本次**：等待下一次正常计划。

同一任务上一轮尚未结束时不会并发启动第二轮，重复触发会合并为一次待执行。

## 通知和运行记录

通知按任务控制，而不是按文件控制：

- 开启通知的传输任务每轮发送一条总览，包含处理、传输、删除、跳过、冲突和失败数量；
- 不再为每个文件发送单独的开始或完成通知；
- 文件夹同步默认静默，详细结果保留在任务自己的运行记录中。

运行记录每页显示 100 条，默认最多保留 300 条，可在任务中调整上限。每条记录可以展开查看文件明细，也可以点击摘要进行筛选。

实时任务没有文件变化时不会不断制造重复历史：连续成功且无变化的检查会合并为一条最新摘要，并显示连续检查次数。真实传输、删除、冲突和失败仍会单独保留，方便追踪实际变更。

## 常见状态

| 状态 | 含义 |
| --- | --- |
| 正在扫描 | 当前正在检查本机或远端目录，尚未得到最终结果。 |
| 运行中 | 当前轮传输或同步正在处理文件。 |
| 正在监控 | 实时任务已启用，当前没有正在执行的传输。 |
| 已暂停 | 任务不会继续触发；保留最近运行或最近同步时间。 |
| 需要处理 | 需要解锁配置、补充凭据、确认主机指纹或处理失败原因。 |

## 使用建议

1. 第一次使用双向任务时，先保持删除传播关闭，手动运行并查看预览和运行记录。
2. 对重要目录先选择冲突保留副本，再逐步启用覆盖或删除策略。
3. 实时任务适合小范围工作目录；大型目录或低带宽连接建议使用分钟级或更长的周期。
4. 如果任务长时间显示“需要处理”，先检查保存的 SSH 连接、配置加密解锁状态和主机指纹变化。
